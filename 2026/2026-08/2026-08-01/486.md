`turn(l, r)` returns the margin on `nums[l..r]`; mover's score minus the other player's.

it's always from the point of view of whoever moves next, so the recursive call hands back the *opponent's* margin. subtracting flips it back to mine; their lead is my deficit.

a tie counts as a win, so the answer is `margin >= 0`.

**v1**

```cpp
class Solution {

    int turn(vector<int> &nums, int l, int r) {

        if (l == r) {
            return nums[l];
        }

        return max(nums[l] - turn(nums, l + 1, r), nums[r] - turn(nums, l, r - 1));
    }

public:

    bool predictTheWinner(vector<int>& nums) {
        int n = nums.size();
        return turn(nums, 0, n - 1) >= 0;
    }

};
```

> Time Complexity : `O(2^n)`
>
> Space Complexity : `O(n)`

elements only come off the ends, so the leftover slice is always contiguous. that makes the state just `(l, r)` so about `n^2 / 2` of them.

v1 walks `2^n` paths through those same states, redoing each one. caching solves this. 

**v2**

```cpp
class Solution {
    vector<vector<int>> memo;
    int turn(vector<int> &nums, int l, int r) {

        if (l == r) {
            return nums[l];
        }

        int &best = memo[l][r];
        if (best > INT_MIN) {
            return best;
        }

        return best = max(nums[l] - turn(nums, l + 1, r), nums[r] - turn(nums, l, r - 1));
    }

public:

    bool predictTheWinner(vector<int>& nums) {
        int n = nums.size();
        memo.assign(n, vector<int>(n, INT_MIN));
        return turn(nums, 0, n - 1) >= 0;
    }

};
```

> Time Complexity : `O(n^2)`
>
> Space Complexity : `O(n^2)`
